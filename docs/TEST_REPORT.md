# Радар 0.1.1-alpha — отчёт

Подготовлено 19 октября 2026 года по времени Екатеринбурга.

## Результат

Собрано собственное Android-приложение `dev.raf.radar`, Android 9+, versionCode 2. Подписанный APK — около 48 МБ. Создан закрытый репозиторий `realalexkorin-alt/radar-android`, загружены исходники, Gradle Wrapper, модульные и интерфейсные тесты, workflows сборки и выпуска.

Это **альфа для проверки интерфейса и механизма получения данных, а не полностью выполненное ТЗ**. Главный пробел — нет подтверждённого источника рублёвой надбавки водителя. Без него уведомления о +200 ₽ не могут работать с реальными данными.

## Что реализовано

- MapLibre Native с подложкой OpenStreetMap, маркеры и светлое/тёмное оформление. Для альфы карта растровая; полноценная векторная тема ещё не подготовлена.
- Сохранённые точки, ввод адреса/координат, настройка тарифов, перенос точки в центр карты, переименование и удаление. Поиск адресов зависит от Android Geocoder; координаты — запасной вариант.
- Динамическая точка «Моя геопозиция», фильтр давности и точности координат, отдельный маркер. При смещении более 250 м старые показания очищаются; ответ для уже покинутой точки отбрасывается.
- Фоновая служба с уведомлением и остановкой; очередь запросов, паузы при ошибках, отметки устаревших данных.
- Виджет поверх приложений: выбранная точка, тарифы, масштаб, размер текста, прозрачность фона, фиксация, перемещение, сворачивание, кнопки карты/обновления/закрытия, перенос тарифов при нехватке ширины.
- Правила уведомлений для каждой точки: по умолчанию выключены, порог в рублях, общий таймер точки для всех её тарифов, пауза 30 минут либо новое уведомление после роста ещё на 50 ₽ от последней отправленной суммы. Срабатывают только при свежем подтверждённом значении RUB; текущий провайдер RUB не выдаёт.
- Проверка GitHub Releases из настроек, загрузка APK и проверка SHA-256, package name, увеличенной версии и того же сертификата перед открытием установщика Android. Полный цикл обновления ещё не испытан на опубликованном канале.
- Экспериментальный вход на сайт Яндекс Такси через WebView и удаление сессии. Пароли не извлекаются; нет JS-моста и отключения проверки TLS. Совместимость авторизованной сессии с API не подтверждена; автоматическое обновление OAuth-токена не реализовано.

## Реальные запросы без авторизации

Выполнены три последовательных исследовательских запроса без cookies и токенов. Создания заказов, входа в чужой аккаунт, имитации водительской личности, обхода CAPTCHA и ротации идентификаторов не было.

Первый минимальный запрос в Москве вернул HTTP 200 и множители, но без идентификаторов тарифов. После включения подробного ответа следующие запросы вернули названия и классы тарифов.

| Публичная точка | Эконом: множитель | Комфорт: множитель | Комфорт+: множитель |
|---|---:|---:|---:|
| Екатеринбург, 56.8389 / 60.5975 | ×2.1502 | Поле отсутствовало | Поле отсутствовало |
| Москва, 55.7558 / 37.6173 | ×2.2348 | ×2.0123 | ×1.6152 |

Это **пассажирские показатели спроса в момент запросов**. Отсутствующее поле не трактуется как нулевая надбавка. В ответах также есть пассажирская цена поездки, но её нельзя выдавать за надбавку водителя. Показания разных точек снимались в разное время и не доказывают стабильность сервиса.

Работа без входа подтверждена для этих исследовательских запросов, а не для всех регионов, сетей и будущих версий API. Совпадение с Яндекс Про не проверено: нет водительской сессии, экрана водителя и синхронного эталонного измерения. Также не проверено длительное использование одной сессии на 20–30 реальных точках.

Окончательный код приложения проверен в коммите `4c97d41297dbc23c9f390dbecf6ca5f58cd61d5b`, запуск CI №5 `39160090399`. После него меняются только документы и доказательства проверок. Визуально просмотрены снимки светлой темы, загрузки карты и увеличенного виджета. При низкой непрозрачности фон другого приложения просвечивает — это ожидаемое поведение настройки, а не гарантированная читаемость на любой подложке. Для читаемости добавлена тень текста.

Снимки получены на виртуальном Android 11 с тестовыми данными, не с реальной надбавкой. Проверка на физическом телефоне остаётся обязательной перед рабочим использованием.

## Частота запросов

По умолчанию — интервал каждой точки 120 секунд и общий разрыв не менее 15 секунд. Для 30 активных точек круг занимает минимум 7,5 минуты плюс задержки сети. Это означает, что уведомления для большой карты не будут мгновенными. 401/403/429 вызывают паузу 15 минут; иные ошибки — увеличение паузы. После остановки служба не перезапускается автоматически.

## Выпуски и обновления

Репозиторий закрытый. Код для чтения Releases и проверки APK реализован, но приложение без GitHub-входа не получает закрытые релизы. Нужен отдельно согласованный публичный репозиторий только для APK либо иной согласованный способ доступа. GitHub PAT в APK не вшит.

В закрытом репозитории подготовлены предварительные релизы `v0.1.0-alpha` и `v0.1.1-alpha`. Для установки предназначен **0.1.1-alpha**: `radar.apk` и `SHA256SUMS`. Это закрытый pre-release, поэтому он не является общедоступным каналом автообновлений. Подпись выпусков одна и та же; versionCode повышен с 1 до 2. Сам цикл обновления через Android Installer не испытан.

Workflow подписанного выпуска подготовлен, но signing secrets в GitHub ещё не настроены. Ключ создан и сохранён отдельно в `radar-signing-backup.zip`. В репозиторий он не загружен. Архив содержит приватный ключ и пароль: его нужно хранить приватно, он потребуется для совместимых обновлений.

Публичная видимость репозитория была отклонена автоматической проверкой, поскольку явно не согласована. Поэтому исходники размещены в закрытом репозитории. Отдельный сервер, база данных и платные ресурсы не создавались.

## Что необходимо до рабочего выпуска

1. Установить происхождение рублёвой надбавки и сравнить её с Яндекс Про в один момент времени и одной точке. Не подменять её пассажирской ценой или множителем.
2. Проверить на физическом телефоне GPS в движении, разрешения, виджет поверх Яндекс Про, выключенный экран, потерю сети, восстановление и расход батареи. Отдельно проверить уведомления Android после подключения реального RUB-провайдера.
3. Выбрать постоянную картографическую подложку, закончить векторную тему и довести внешний вид по фактическим скриншотам телефона.
4. Настроить приватные signing secrets и согласованный канал релизов, затем проверить обновление версии без потери точек и настроек.

Все эти пункты остаются открытыми. APK предназначен для первоначальной установки и проверки; утверждать, что всё ТЗ уже работает, оснований нет.
