# Радар 0.1.4-alpha

Дата: 19 октября 2026. Пакет `dev.raf.radar`, versionCode 5, Android 9+.

## Изменения

- Канал обновлений закреплён за публичным репозиторием `realalexkorin-alt/radar-android`. Старое редактируемое значение репозитория игнорируется.
- «Настройки → Проверить обновления» сравнивает версии до загрузки и предлагает актуальный `radar.apk` из опубликованного GitHub Release. Коммиты без релиза не являются обновлением.
- Добавлен прогресс загрузки. Перед установкой проверяются SHA-256, пакет, более высокий versionCode и совпадение подписи. Скачанный APK сохраняется для продолжения установки после выдачи разрешения; повторное нажатие кнопки также использует сохранённый файл.
- При входе проверяются точная геопозиция, уведомления, показ виджета поверх других приложений и установка обновлений. После отказа проверка повторяется при следующем входе. При системном запрете повторного запроса открываются настройки нужного разрешения. Возврат из настроек перепроверяет доступ.
- Мониторинг требует геопозицию и уведомления. Виджет требует разрешение на наложение, установка — разрешение на APK. Дополнительных разрешений в манифест не добавлено.

## Проверки

Локально: 45 модульных тестов без ошибок; `lintRelease`, `assembleRelease`, компиляция Android-тестов успешны. Lint не содержит ошибок; остаются три прежних предупреждения о JavaScript экрана входа, доступности жестов и строках интерфейса.

Эмуляторы Android 11 (API 30) и Android 13 (API 33): по 1 изолированному сценарию разрешений и по 10 основным сценариям, все успешно. Финальный CI: https://github.com/realalexkorin-alt/radar-android/actions/runs/39202095616 . Проверяемый коммит: `515a9875fd91f0b72a7cdbc8e9f139f0b02355c4`.

Сценарии: отказ в геопозиции, запрет мониторинга без доступа, повторный системный запрос при новом входе, переход в настройки наложения и возврат без выдачи доступа; отдельный вход со всеми выданными разрешениями; закреплённый канал обновлений; отказ от повреждённого APK; прежние сценарии карты, сохранения точки, настроек, тем, виджета и жестов.

В Android 11 изменение app-op `REQUEST_INSTALL_PACKAGES` завершает процесс приложения, включая тестовый процесс. Системный журнал подтвердил причину `REQUEST_INSTALL_PACKAGES changed.`. Поэтому тестовый стенд выдаёт специальные разрешения до запуска основной instrumentation-сессии. Приложение таких shell-операций не выполняет.

## Практические границы

Установка требует подтверждения в системном установщике Android. Эмуляторы не заменяют проверку на конкретном телефоне и его оболочке. Полная установка через системный установщик поверх пользовательской сборки и продолжение установки после разрешения на реальном телефоне требуют проверки пользователем. Расчёт надбавок, API сервиса и жесты виджета этим патчем не изменены.
