# 0.1.33 · история надбавок и погоды

Сбор успешных значений Эконома в рублях только по включённым сохранённым точкам. GPS-траектории и имена не отправляются. Целевой шаг 5 минут; ноль сохраняется, ошибки/устаревшие значения исключены. Интервал сохранённых точек ограничен сверху пятью минутами, но глобальная очередь/паузы API сохранены — точный шаг при сбоях/большом числе точек не гарантируется.

Локальная очередь до5000/2МБ, срок7д, сохраняется на диске; отправка отдельным потоком пакетами20, авторизованная сессия, изоляция аккаунтов. Сервер повторно проверяет время/координаты/рубли, устраняет дубли по источнику/пятиминутному окну. Погода Open-Meteo: часовые модельные температура, ветер м/с, осадки/дождь/снег/WMO-код; сохраняется время и источник. Запрос погоды округлён до0.1° и кэшируется30мин. Сбой погоды не блокирует надбавку, отсутствующее значение остаётся NULL. Это модельная погода, а не измерение метеостанции ровно в момент запроса.

Области постоянного центра, радиус1000м, без цепочного слияния; доступ к исходной истории закрыт существующим ключом чтения диагностики. Хранение90д, очистка pg_cron ежечасно. Включение прогнозирования управляет отображением и не отключает накопление. Сбор начинается после установки и при работающем мониторинге; закрытое/остановленное приложение не получает новые цены.

Проверка: два JVM-сценария очереди + контракт backend, серверная проверка отдельно. История не позволяет обещать качество прогноза через день; сначала проверяем полноту, частоту, нули и погодное покрытие. Перед расширением распространения описать сбор в соглашении. Погода: https://open-meteo.com/en/docs (атрибуция Open-Meteo).
